# 5. API規格

> 本章定義後端 API 之端點、參數與回傳結構。欄位之顯示標籤與介面呈現規則詳見 §2 資料規格。
> 

# 5.1 通則

| 項目 | 規格 |
| --- | --- |
| 通訊協定 | HTTPS |
| 資料格式 | JSON（照片上傳為 multipart/form-data） |
| 認證方式 | Bearer Token，效期永久 |
| 帳號建立 | 調查人員、內業人員可透過 `/auth/register` 自助註冊；**管理者帳號由後端直接建置，不提供註冊或 API 開通** |
| 日期傳輸格式 | 西元 ISO 8601（`YYYY-MM-DD`），民國年轉換由前端處理 |
| 座標系統 | WGS84（EPSG:4326），圖層資料為 GeoJSON |
| 土地識別碼 | 路徑參數 `{key_no}` 為系統土地唯一識別碼，Char(15)，見 §2.2.1 |
| 系統帶入欄位 | 勘查時間、勘查人員由後端於送出時寫入，前端不傳送；提交批次不於此處設定，另由批次設定端點寫入 |
| 現況照片 | 固定 4 張，統一 4:3；張數不符時回傳 422 |

# 5.2 端點清單

## 認證與帳號

| 方法 | 端點 | 說明 |
| --- | --- | --- |
| POST | `/auth/register` | 註冊，欄位詳 §2.2：帳號、密碼、廠商名稱、作業性質（外業人員／內業人員）、姓名 |
| POST | `/auth/login` | 登入，回傳 Token、使用者姓名、廠商與角色權限 |
| POST | `/auth/logout` | 登出 |

## 圖台與土地查詢

| 方法 | 端點 | 說明 |
| --- | --- | --- |
| GET | `/map/scopeSearch` | 依可視範圍取得地籍 GeoJSON |
| GET | `/parcel/list` | 土地清單，支援 §2.6 篩選條件與分頁 |
| GET | `/parcel/{key_no}` | 土地詳情，回傳「土地資料」頁籤（土地標示＋套匯圖資，唯讀）與「實地勘查土地現況」頁籤資料；狀態為「已修正」時，一併回傳 2.4.2.2 退回快照，供比對顯示 |
| GET | `/parcel/{key_no}/history` | 該土地各期調查紀錄 |

## 實地勘查土地現況

| 方法 | 端點 | 說明 |
| --- | --- | --- |
| POST | `/survey` | 首次送出。僅調查人員可用；**僅當該土地目前狀態為「未調查」時允許呼叫**，狀態非未調查時回傳 409。接收欄位 4~10（土地坐落、現場勘查土地情形、占用型態、占用戶數、占用門牌號、備註、現況照片×4），成功後狀態變為「外業調查完成」 |
| PUT | `/survey/{survey_id}` | 修改既有資料之欄位 4~9（現況照片另經 photo 端點更新）。**僅當該土地狀態非「未調查」時允許呼叫**，未調查時無資料可編輯，回傳 409。欄位 1~3（勘查時間、勘查人員、提交批次）維持原值，不接受修改。呼叫者為調查人員且目前狀態為「退回」時，若請求帶 `resubmit: true` 並經前端確認彈窗確認，狀態自動變更為「已修正」；呼叫者為內業人員／管理者時，狀態不因此變更 |
| POST | `/survey/{survey_id}/photo` | 上傳／替換現況照片，固定 4 張，4:3 |
| POST | `/survey/{survey_id}/approve` | 查核通過。狀態須為「外業調查完成」或「已修正」，變更為「已查核」。僅內業人員、管理者 |
| POST | `/survey/{survey_id}/reject` | 退回，需帶退回意見。狀態須為「外業調查完成」或「已修正」，變更為「退回」。僅內業人員、管理者 |

## 清單、批次與匯出入

| 方法 | 端點 | 說明 |
| --- | --- | --- |
| POST | `/parcel/batch` | 批次設定：將目前篩選結果之土地統一設定提交批次。僅內業人員、管理者 |
| POST | `/export` | 依篩選條件產製成果清冊，格式詳 §2.8 |
| POST | `/import/parcel` | 土地批次匯入（清冊匯入，屬管理／建置作業，非日常操作） |

## 儀表板

| 方法 | 端點 | 說明 |
| --- | --- | --- |
| GET | `/dashboard/progress` | 調查進度統計：外業調查完成、已查核之筆數與百分比 |
| GET | `/dashboard/progress/district` | 分區進度統計：六個行政區之外業調查完成率、已查核率 |

## 代碼表

| 方法 | 端點 | 說明 |
| --- | --- | --- |
| GET | `/code/{code_type}` | 取得代碼表選項，供前端下拉／複選使用（含廠商名單、現場勘查土地情形、備註等） |

# 5.3 錯誤碼

| 狀態碼 | 說明 | 前端行為 |
| --- | --- | --- |
| 200 | 成功 | — |
| 401 | 未登入或 Token 失效 | 見 §3.3 |
| 403 | 權限不足 | 見 §3.3 |
| 404 | 查無資料 | 見 §3.3 |
| 409 | 資料衝突或狀態不允許（如對「未調查」土地呼叫 PUT /survey） | 見 §3.3 |
| 422 | 參數或驗證錯誤（如照片非 4 張） | 見 §3.3 |
| 500 | 伺服器錯誤 | 見 §3.3 |

# 5.4 待補項目

| 項目 | 說明 |
| --- | --- |
| 詳細請求／回應結構 | 各端點之 request body 與 response schema |
| 代碼表 code_type 清單 | 對應 §2.2 廠商名單、§2.4.2.1 現場勘查土地情形／備註等選項之代碼 |
| 匯出格式細節 | §2.8 目前以原始清冊檔案為範本附件，尚待轉為明確欄位對應規則 |
| 匯入規則 | 匯入格式、檢核項目與錯誤回報方式 |
| 套匯圖資來源 | 圖資提供單位、更新頻率；系統僅顯示原始值，不進行比對或計算 |
| 分區清冊匯出 | 待確認是否納入及欄位範圍，詳母頁 §五 |
| resubmit 確認機制 | PUT /survey 之 `resubmit` 參數為本次同步時的設計推論，實際前後端合約待確認 |
