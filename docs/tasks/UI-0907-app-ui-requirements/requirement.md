# Requirement

## Background
- 現有 APP 規格分散於系統規格文件與 Figma 七組流程節點，尚缺可由 AI 直接追蹤至畫面、元件、狀態與驗證的 UI requirement。
- 本文件整理 Android 行動版的登入／註冊、圖台、底圖、土地查詢、調查填報、退回修正與確認提示，不將設計稿中的 iOS 樣式納入實作範圍。

## Goal
- 建立 Android 9+ 可執行、可驗證且可追溯至 Figma 與系統規格的 UI requirement 架構，作為後續 Planning、Implementation 與 Verification 的輸入。

## Functional Requirements
- `FR-001 認證入口`：登入頁須提供帳號、遮罩密碼、4 碼數字驗證碼、驗證碼重整、記住我、登入及前往註冊；成功後進入圖台，失敗時保留輸入並顯示「帳號、密碼或驗證碼錯誤」。
- `FR-002 註冊`：註冊頁須依序提供帳號、密碼、確認密碼、廠商名稱、作業性質與真實姓名，並提供取消／返回及完成；帳號僅限英數且最多 30 字元，密碼至少 8 碼且兩次輸入一致，廠商選項由後端名單提供；成功後返回登入頁。
- `FR-003 圖台首頁`：登入後預設進入全螢幕圖台；頂部提供漢堡選單、土地關鍵字搜尋及通知入口，底部提供三種底圖切換，右下提供定位與土地搜尋／篩選入口。
- `FR-004 底圖切換`：提供電子地圖、正射影像圖、地形圖三種互斥選項，預設電子地圖；切換只改變底圖，土地標的與使用者位置等業務覆蓋物須維持。
- `FR-005 土地查詢`：接受地號、土地坐落或土地編號關鍵字；找到資料時定位地塊並開啟土地摘要 sheet，查無資料時保留關鍵字並顯示「查無資料」。
- `FR-006 土地詳情`：點擊地塊或查詢結果後開啟可上滑的土地詳情；頂部顯示調查狀態、土地編號、地號與現場勘查土地情形，內容以「土地資料」及「實地勘查土地現況」兩頁籤呈現。
- `FR-007 土地資料頁籤`：顯示土地標示 8 欄及套匯圖資 2 欄，全部唯讀；空值、日期、數值與複選值依資料規格的共通顯示規則呈現。
- `FR-008 新增調查`：未調查土地可由具權限角色進入實地勘查頁籤並新增；勘查時間、勘查人員、提交批次唯讀，土地坐落、現場勘查土地情形、占用型態、占用戶數、占用門牌號、備註與現況照片依資料規格輸入。
- `FR-009 條件欄位`：現場勘查土地情形為「無占用」時，須隱藏並清空占用型態、占用戶數與占用門牌號；非「無占用」時三欄必填，且占用戶數為大於等於 1 的整數。
- `FR-010 現況照片`：僅允許開啟相機現場拍攝，不提供相簿選取；送出時必須正好 4 張 4:3 照片，縮圖顯示拍攝時間並可逐張刪除重拍。
- `FR-011 首次送出`：通過欄位與照片驗證後送出未調查土地，成功將狀態更新為「外業調查完成」並顯示成功訊息；錯誤時保留已填內容及照片。
- `FR-012 退回通知`：圖台通知入口顯示退回土地清單，每筆至少包含退回狀態、土地編號及退回意見摘要；點擊後進入該筆實地勘查土地現況並醒目顯示完整退回意見。
- `FR-013 退回修正`：退回資料允許外業人員修改可輸入欄位；儲存編輯內容後，使用者須再觸發「確認修正」，並於 Android 確認對話框確認後才變更為「已修正」。
- `FR-014 編輯離開提醒`：編輯期間以返回或關閉離開且存在未儲存內容時，顯示 Android 確認對話框，提供「繼續編輯」與「捨棄編輯」；前者保留內容，後者還原至進入編輯前資料並離開。
- `FR-015 刪除照片提醒`：刪除縮圖前顯示 Android 確認對話框，提供「取消」與「刪除」；只有確認刪除後移除該張照片並重新出現拍攝入口。
- `FR-016 登出與工作階段`：漢堡選單顯示帳號名稱、圖台、儀表板及登出；Token 效期永久，登出清除本機 Session Token 並返回登入頁，401 亦返回登入並顯示逾期提示。
- `FR-017 錯誤處理`：403 不離開目前畫面並提示權限不足；404 在目前面板顯示查無資料；409／422 對應欄位顯示錯誤並保留輸入；500 顯示系統錯誤與重試入口。

## Non-functional Requirements
- 支援 Android 9 以上；Figma 的 402×874 為直向參考畫布，不得以固定像素假設取代不同螢幕尺寸、安全區域、鍵盤與字級縮放的適配。
- 所有可操作圖示須提供可讀的無障礙名稱，觸控目標至少符合 Android 平台建議，文字放大後不得遮蔽主要操作。
- 表單送出、照片上傳與狀態變更須防止重複觸發；載入中應禁止重複提交並保留可恢復的使用者輸入。
- 密碼與 Token 不得出現在畫面截圖、一般紀錄或錯誤訊息；登出與 401 導回登入後不得保留可用 Token。
- 所有畫面文案使用繁體中文；日期顯示民國年，API 傳輸仍使用 ISO 8601 西元日期。

## Acceptance Criteria
- `AC-001`：未登入啟動 APP 時顯示登入畫面，帳號、密碼、驗證碼皆可輸入，密碼遮罩，驗證碼可重整，且可前往註冊。
- `AC-002`：輸入合法登入資料後進入圖台；輸入無效資料時不離開頁面、保留帳號與「記住我」狀態並顯示「帳號、密碼或驗證碼錯誤」。
- `AC-003`：註冊畫面顯示六組規定欄位及取消／完成操作；帳號非英數或超過 30 字元、欄位缺漏、密碼不符或格式不符時阻止提交並在欄位旁提示；成功後返回登入頁。
- `AC-004`：登入後圖台顯示頂部三個入口、底圖選擇器及定位／搜尋操作，開啟漢堡選單可看見帳號名稱與登出。
- `AC-005`：三種底圖可互斥切換且電子地圖為初始值；切換後土地標的及使用者位置覆蓋物仍存在。
- `AC-006`：以地號、土地坐落或土地編號可執行關鍵字查詢；有結果時定位並開啟該土地摘要，無結果時顯示查無資料且保留輸入。
- `AC-007`：由地塊或結果開啟的詳情含固定摘要與兩頁籤，土地資料 10 欄唯讀且顯示格式符合資料規格。
- `AC-008`：未調查土地可開啟新增表單，三個系統帶入欄位唯讀，七個使用者資料項目使用規定元件與選項。
- `AC-009`：選取「無占用」會隱藏並清空三個占用欄位；改選有占用選項後，三欄恢復且在送出前必填，占用戶數拒絕 0、負數、小數與非數字。
- `AC-010`：只能透過相機取得照片；未滿或超過 4 張、非 4:3 時不得完成送出，恰為 4 張時顯示四張縮圖及拍攝時間。
- `AC-011`：首次送出成功顯示成功訊息並更新為外業調查完成；401／403／404／409／422／500 各依 `FR-017` 呈現且不造成未提交資料無提示遺失。
- `AC-012`：通知入口可呈現退回清單，點擊其中一筆會開啟正確土地，並在詳情頂部顯示該筆完整退回意見。
- `AC-013`：退回資料完成編輯後，只有在 Android 確認對話框選擇確認才變更為已修正；取消確認時維持退回狀態與已編輯內容。
- `AC-014`：有未儲存變更時離開會顯示「繼續編輯／捨棄編輯」；兩個操作分別保留編輯狀態或還原並離開，沒有未儲存變更時不顯示此提醒。
- `AC-015`：照片刪除只有在確認後生效；取消時照片不變，確認後數量減一並顯示可補拍入口。
- `AC-016`：登出後返回登入且受保護畫面不可再使用；401 亦返回登入並顯示「登入已逾期，請重新登入」。
- `AC-017`：在 Android 9 及一個較新 Android 版本，以最小／一般支援寬度、系統字級放大及螢幕鍵盤覆蓋情境檢查時，主要內容可捲動、主要操作可觸及且無文字截斷造成的功能阻斷。

## Constraints
- 產品目標平台為 Android 9+、Kotlin；Figma 內的 iOS 對話框僅供跨平台文案參考，不是 Android 視覺驗收來源。
- `key_no` 是查詢與 API 路徑的唯一識別碼；`land_no` 只用於顯示與匯出。
- 調查狀態只能經核定動作流轉，不提供直接指定。
- 後端送出時寫入勘查時間與勘查人員；前端不得修改或傳送這兩欄。
- 本需求不新增 WEB 土地清單、WEB 查核／退回、匯出、匯入及部署行為。
- 本 requirement 目前為草案；`KCF-003`、`KCF-004` 與正式設計核定未解決前不得宣告整體 Requirement Baseline Approved。

## Open Questions
- `KCF-003`：外業人員是否可在 APP 編輯「外業調查完成」資料（非退回修正）尚未由角色、狀態及 API 規格一致定義。
- `KCF-004`：Figma 有退回通知中心，但正式介面、Sitemap 與 API 規格缺少通知清單／已讀機制，尚待產品與 API 權責者定義。
